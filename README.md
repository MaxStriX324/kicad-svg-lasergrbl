# KiCad SVG → PNG 1:1 для LaserGRBL / CNC3018

**Портфолио:** [страница лабораторной автоматизации и остальные инструменты](https://maxstrix324.github.io/project/lab-automation/). Ниже приведены актуальные возможности, ограничения и инструкции этого репозитория.

Пакетная конвертация экспортированных из **KiCad 10** файлов `.svg` в монохромные `.png` и готовые растровые G-code `.nc` для **LaserGRBL 4.9.4** (Windows). Для каждой платы создаётся отдельный TXT с физическими размерами и инструкцией по импорту; общий отчёт автоматически открывается в Блокноте.

**Назначение:** обработка слоя меди / маски лазером, например удаление защитной краски перед травлением. В стандартной полярности **чёрное — обрабатываемая область, белое — не обрабатывается**. Полярность следует проверять для конкретной технологии и настроек импорта.

## Быстрый запуск (Windows)

1. Скачайте проект через **Code → Download ZIP**, распакуйте.
2. Запустите `install.cmd`: он проверит локальную `.venv`, при повреждении пересоздаст её и установит недостающие Python, PyMuPDF и Pillow. Интернет нужен при первоначальной установке или загрузке отсутствующих библиотек.
3. Экспортируйте нужные слои из KiCad в **SVG**, включив *Fit page to board* (подгонку страницы к плате).
4. Скопируйте все SVG в папку с `start.cmd`.
5. Запустите **`start.cmd`**. Он автоматически восстановит отсутствующее или неработающее Python-окружение, затем создаст папку проекта по имени файлов и сформирует PNG, NC и отчёты.

Получите:

| Вход | Выход |
|---|---|
| `EVSE-F_Cu.svg` | `_EVSE/EVSE-F_Cu_laser.png`, `_EVSE/EVSE-F_Cu_laser.nc`, TXT |
| `EVSE-B_Cu.svg` | `_EVSE/EVSE-B_Cu_laser.png`, `_EVSE/EVSE-B_Cu_laser.nc`, TXT |
| Все SVG | Общий `LASERGRBL_SETTINGS.txt`, CSV и отчёты по папкам |

Настройки задаются в начале `start.cmd`:

```bat
set "DPI=508"
set "INVERT=0"
set "MIRROR_X=0"
set "THRESHOLD=128"
set "GCODE_MODE=binary"
set "REBUILD_EXISTING=0"
set "GCODE_LINES_PER_MM=10"
set "GCODE_FEED=1000"
set "GCODE_POWER=1000"
```

- **508 DPI** = номинально 20 пикселей/мм, шаг 0,05 мм.
- `INVERT=1` меняет чёрное и белое.
- `MIRROR_X=1` отражает изображение по горизонтали. Не включайте зеркало автоматически для обратного слоя: ориентируйтесь на технологию установки платы.
- `THRESHOLD` задаёт порог чёрно-белого растра.

## Папка проекта и автоматический G-code NC

В корне конвертера лежат `EVSE-F_Cu.svg` и `EVSE-B_Cu.svg`. Утилита определяет общее имя до суффиксов `-F_Cu` и `-B_Cu`, создаёт каталог `_EVSE` рядом с `start.cmd` и **после успешной генерации** перемещает туда оба SVG. Разные платы собираются в разные каталоги. Файлы SVG с другими именами по-прежнему преобразуются в корне. При повторном импорте изменённого SVG предыдущий исходник сохраняется в `_EVSE/_backups/`.

```text
kicad-svg-lasergrbl/
├── start.cmd
├── update.bat
├── _EVSE/
│   ├── EVSE-F_Cu.svg
│   ├── EVSE-B_Cu.svg
│   ├── EVSE-F_Cu_laser.png
│   ├── EVSE-B_Cu_laser.png
│   ├── EVSE-F_Cu_laser.nc
│   ├── EVSE-B_Cu_laser.nc
│   ├── EVSE-F_Cu_laser_grayscale.nc (после режима grayscale)
│   ├── EVSE-B_Cu_laser_grayscale.nc (после режима grayscale)
│   ├── EVSE-F_Cu_laser_settings.txt
│   ├── EVSE-B_Cu_laser_settings.txt
│   ├── LASERGRBL_SETTINGS.txt
│   └── lasergrbl_sizes.csv
└── LASERGRBL_SETTINGS.txt  (общая сводка)
```

G-code формируется напрямую из монохромного PNG. Он использует `G21` (мм), `G90` (абсолютные координаты), `G94`, `M3 S0`, горизонтальную змейку снизу вверх, `M5` и возврат к `X0 Y0`. Ноль — **левый нижний угол страницы SVG**, а не обязательно угол физического контура платы. **Чёрное = лазер включён**, белое = лазер выключен. По оси Z перемещений нет.

В начале `start.cmd` доступны:

По умолчанию `GCODE_MODE=binary` и `GCODE_LINES_PER_MM=10`. Для сравнения используйте `GCODE_MODE=grayscale`; для более плотного растра — `GCODE_LINES_PER_MM=20`. Скорость `F1000` и `S1000` соответствуют ранее приложенному примеру, но **не являются рекомендованными параметрами для любого лазера**.


```bat
set "GCODE_LINES_PER_MM=10"
set "GCODE_FEED=1000"
set "GCODE_POWER=1000"
```

Параметр `GCODE_MODE` принимает `binary` (по умолчанию) или `grayscale`. В `binary` лазер переключается только между `S0` и `GCODE_POWER`, с порогом чёрно-белого PNG. В `grayscale` программа **повторно отрисовывает исходный SVG в градациях серого без порога `THRESHOLD`**, учитывает `INVERT` и `MIRROR_X`, после чего преобразует яркость пикселя в `S` от нуля до максимума. Это создаёт промежуточные значения мощности на сглаженных границах, а не имитирует их из уже бинарного PNG.

`GCODE_LINES_PER_MM` поддерживает **10 или 20**. Выбранная плотность применяется **одновременно к X и Y**: 10 → шаг 0,1 × 0,1 мм; 20 → 0,05 × 0,05 мм. Формируются растровые строчки змейкой снизу вверх. PNG всегда остаётся 508 DPI (около 20 пикселей/мм), независимо от плотности NC.

Режимы сохраняются в отдельных файлах: `Binary` создаёт `EVSE-F_Cu_laser.nc` (как прежде), а `Grayscale` создаёт `EVSE-F_Cu_laser_grayscale.nc`. **Оба файла могут находиться в `_EVSE` одновременно**. Настройка `REBUILD_EXISTING=1` заставляет `start.cmd` заново обработать SVG уже внутри папок `_ПРОЕКТ`, без ручного копирования SVG в корень. При `REBUILD_EXISTING=0` обрабатываются только новые SVG из корня. Для сравнения просто переключите режим, поставьте `REBUILD_EXISTING=1` и запустите программу ещё раз.

Градации `S` не гарантируют линейную глубину удаления краски: результат зависит от `$30`, `$32`, мощности, скорости, динамики лазера и покрытия. В частности, изображение на стадии импорта в LaserGRBL может давать другие промежуточные значения S. Результаты будут геометрически близкими, но **не побайтово идентичными**.

**Перед работой на станке** обязательно проверьте `$30` (если `255`, задайте `GCODE_POWER=255`), `$32`, расположение рабочего нуля, размеры, направление осей, полярность и масштаб. Откройте `.nc` в LaserGRBL, просмотрите траектории, выполните контрольную рамку при выключенном луче. Значение `S1000` взято из примера и не является безопасным универсальным режимом.

Файл проекта LaserGRBL `.lps` содержит сериализованные параметры конвертации и изображение; программа не генерирует `.lps`, поскольку для запуска достаточно `.nc`.

## LaserGRBL 4.9.4: импорт 1:1

1. **File → Open File** → `*_laser.png`.
2. В окне импорта растра можно выбрать **Line To Line Tracing**; проверьте, какие области будут гравироваться.
3. В **Target Image** отключите **Autosize**, вручную установите **Size W**, указанную в `*_laser_settings.txt`, и проверьте **Size H**.
4. Если размер изображения фиксирован по пропорциям, высота может отличаться от исходного SVG на несколько микрометров. Точная рассчитанная разница указывается в отчёте.
5. Не включайте Crop/Auto crop, дополнительное масштабирование, поворот или зеркало без необходимости.
6. Проверьте *frame* при выключенном луче, калибровку GRBL `$100`/`$101`, масштаб по тестовому размеру и диаметр пятна лазера.

**Точность:** утилита считывает физические размеры **страницы SVG**, не обрезает её и рассчитывает растровую сетку, близкую к заданному DPI. Это не означает гарантированную точность станка 1:1: механическая калибровка и масштаб импорта должны быть проверены. Если KiCad экспортировал поля вокруг платы, они входят в размеры; для реального контура применяйте *Fit page to board*.

## Запуск из командной строки

После `install.cmd`:

```bat
.venv\Scripts\python.exe svg_to_png_batch.py --dpi 508 --invert 0 --mirror-x 0 --threshold 128
```

Конвертер обрабатывает все `.svg` **рядом с самим Python-скриптом**. Для другой папки предусмотрен `--folder "C:\path\to\svg"` (не добавляйте `\` непосредственно перед закрывающей кавычкой). Некорректные единицы размера SVG отклоняются с ошибкой, а не угадываются.


**Если установленный Python обновился или был удалён:** запускайте `start.cmd` — он обнаружит ошибку и вызовет восстановление через `install.cmd`. Файлы SVG, PNG и TXT при этом не удаляются; пересоздаётся только временное окружение `.venv`.

## Проверка

```bat
.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты проверяют единицы измерения, пиксельный масштаб, чёрно-белый вывод, инверсию и создание отчёта. Данные пользовательских плат не включены в репозиторий. Сгенерированные PNG/TXT, исходные SVG и виртуальное окружение исключены через `.gitignore`.

Для деталей на русском также имеется `README_RU.txt`.

## Обновление программы через Git (update.bat)

После установки запустите **`update.bat`** двойным щелчком. Для Git-копии программа проверит адрес `origin`, отсутствие несохранённых изменений в отслеживаемых файлах, затем выполнит `git fetch` и `git merge --ff-only` основной ветки `main`. Принудительный сброс (`reset --hard`) не применяется. При необходимости Git for Windows устанавливается через `winget` в профиль пользователя; если установка недоступна, утилита сообщит об этом.

**Если проект был скачан через Download ZIP:** `update.bat` не перезаписывает старую папку. Он создаёт отдельный Git-клон `<имя-репозитория>-git` рядом с ней (повторный запуск обновит этот клон), после чего проверяет установку. Для дальнейшей работы используйте новый каталог; свои SVG, DRL, CSV, архивы и локальные настройки перенесите самостоятельно, если они нужны в новой копии. Не перемещайте `.venv`: окружение будет создано заново.

**Если Git сообщает о локальных изменениях** (например, редактировали отслеживаемый `settings.json` или скрипты), обновление остановится, не затирая их. Сохраните отдельную копию конфигурации, затем зафиксируйте, отмените или перенесите изменения через Git и повторите запуск.
- Утилиты на Python после обновления запускают свой `install.bat` или `install.cmd` в тихом режиме для проверки зависимостей. Готовые результаты, входные файлы и рабочие папки не удаляются.
